# Reproducibility guide: Track C GPU appliance ("lazarus")

How to rebuild every artifact of this project from a clean clone of the Git repository, what
is pinned, how determinism is achieved, how it was verified, and what is still not
bit-for-bit reproducible. Every command below is a script in this repository.

## 1. What you need

| Item | Notes |
|---|---|
| Linux build host, x86-64 | built and tested on CachyOS (Laptop 1); any distro with the tools below |
| Podman (rootless) | all builds run in pinned containers, the host is not modified |
| QEMU + OVMF (UEFI firmware), KVM | boot tests (`test/qemu-smoke.sh`, `test/iso-smoke.sh`) |
| `curl`, `bsdtar`, `gpg`, `zstd`, `sgdisk`/`sfdisk` | key/kernel downloads and checks on the host |
| ~30 GB free disk | peak during image builds; outputs go to `out/`, downloads to `cache/` (both gitignored) |
| Internet for the first build | afterwards rebuilds are offline (package caches in `cache/`) |

Only for the measurement and USB parts: a USB stick (64 GB for both systems, 8 GB for the
portable image), `host/install-usb-access.sh` once (udev rule giving your user write access
to those two sticks only, matched by serial number).

Not in Git (secrets, recreate locally): `cache/wifi.env` (hotspot SSID/password, from
`baseline/wifi.env.example`), `~/.ssh/trackc_ed25519` (lab SSH key: `ssh-keygen -t ed25519 -N '' -f ~/.ssh/trackc_ed25519`),
`out/dev-secrets/authorized_keys` (copy of that public key), `cache/baseline-credentials.txt`
(generated by the baseline installer). The release and portable images contain none of these.

## 3. Build everything from a clean clone

```sh
git clone <repo> && cd <repo>

# 0. Keys and kernel source (verified against the pins)
build/nvidia/fetch-keyring.sh            # NVIDIA Debian 13 + Ubuntu 24.04 repo keys
build/kernel/fetch-source.sh             # linux-6.12.118.tar.xz

# 1. Package cache for the CUDA containers (Ubuntu 24.04 + NVIDIA repo, ~5.7 GB, once)
baseline/prefetch-debs.sh

# 2. Containers (offline, from the cache)
build/container/build-bench-image.sh     # -> out/trackc-bench.tar      (boot health check)
build/container/build-cudadev-image.sh   # -> out/trackc-cuda-dev.tar   (cuda-dev / lazarus toolkit)

# 3. Kernels (pinned builder container, ~5 min each)
build/kernel/run.sh                      # -> out/kernel/      (laptop kernel, on the sticks)

# 4. Root filesystems + images
build/builder.sh build/rootfs/build-rootfs.sh release trackc && build/builder.sh build/image/build-image.sh release
build/builder.sh build/rootfs/build-rootfs.sh dev trackc     && build/builder.sh build/image/build-image.sh dev
build/builder.sh build/rootfs/build-rootfs.sh portable trackc && build/builder.sh build/image/build-image.sh portable
build/builder.sh build/rootfs/build-rootfs.sh portable debian-iso && build/builder.sh build/image/build-iso.sh   # ISO: Debian kernel + signed shim/GRUB
# (each rootfs build leaves out/rootfs-<variant>; remove it after the image step:
#  podman unshare rm -rf out/rootfs-<variant>)

# 5. Boot tests (QEMU/KVM, UEFI)
test/qemu-smoke.sh out/<variant>/disk.img          # read-only root self-test + persistence
test/iso-smoke.sh                                  # ISO as CD-ROM and as USB stick
```

Outputs:
| Artifact | Path |
|---|---|
| Release image (graded, measured) | `out/release/{rootfs.squashfs,trackc.efi,sizes.txt,packages.tsv}` |
| Dev image (64 GB measurement stick) | `out/dev/…` |
| Portable flashable image | `out/portable/trackc-gpu-appliance.img` (+ `.img.zst`, `SHA256SUMS`) |
| Live ISO (other laptops) | `out/iso/trackc-gpu-appliance.iso` (+ `SHA256SUMS`) |

dev only: needs `cache/wifi.env` and `out/dev-secrets/authorized_keys` (section 1).

```sh
measure/run-target.sh --host <ip> --mac <mac> --name <n> --phase <p> [--user trackc] ...

ssh lazarus@<ip> 'bash -s' < measure/verify-appliance.sh   # final acceptance checks
```
Writing the portable image or ISO to a stick: see `docs/portable-image.md` and `docs/iso.md`
(`dd`, Rufus in DD mode, or balenaEtcher).

## 5. How determinism is achieved

* **Pinned inputs** (section 2): snapshot date instead of "latest", digests instead of tags,
  versions on every NVIDIA package, SHA-256/fingerprint checks on every download that is not
  signature-checked by apt.
* **Containers for every build step**: builder and kernel-builder images built from a pinned
  digest and the snapshot; the host system is not involved.
* **Timestamps**: `SOURCE_DATE_EPOCH` for mksquashfs (`-reproducible`), the UKI, ext4
  (`E2FSPROGS_FAKE_TIME`), the ISO tree, and the kernel (`KBUILD_BUILD_TIMESTAMP`).
* **Build identity**: `KBUILD_BUILD_USER/HOST` fixed; NVIDIA's module stamp pinned
  (`NV_BUILD_USER`, `NV_BUILD_HOST`, `DATE`), which otherwise embeds `user@host` and the date
  into `nvidia.ko` and `nvidia-modeset.ko`.
* **Fixed identifiers**: GPT disk/partition GUIDs, FAT volume IDs, ext4 UUID and hash seed,
  system user `bench` UID/GID 900.
* **No build-host leakage**: compilers, headers and DKMS are purged after building the
  NVIDIA modules; apt lists and repo configuration are removed from the image; SSH host keys
  are not shipped in the portable image.

## 6. Verification (recorded in `docs/results/phase7/`)

Two clean builds of the release image, compared by SHA-256:

| Output | Result (final code, 2026-11-21) |
|---|---|
| `rootfs.squashfs` | identical (`52d934a2b1b73b63…`) |
| `trackc.efi` (kernel + initramfs) | identical (`7a62fc79d61f4245…`) |
| `packages.tsv` | identical (`6c10a2ba0266621c…`) |

Files: `hashes-final-buildA.txt`, `hashes-final-buildB.txt`, `compare-final.txt`. Earlier
rounds (`hashes-build1/2`, `compare-trackc.txt`) document how the last difference (the NVIDIA
build stamp) was found and fixed.

To verify yourself: build the release image twice (`rm -rf out/release` in between) and
compare `sha256sum out/release/{rootfs.squashfs,trackc.efi,packages.tsv}`.

## 7. Known limits of reproducibility (honest list)

* **Kernel packages**: rebuilding the kernel gives the identical `.config`, but the
  `linux-image`/`linux-headers` `.deb` files are not yet bit-identical between kernel builds
  (`compare-kernel.txt`). The image is reproducible from a given set of kernel packages.
* **Same machine**: both verified builds ran on Laptop 1; a second, different build machine
  was not tested.
* **NVIDIA repositories are not snapshotted**: packages are pinned by exact version, so the
  same files are used as long as NVIDIA keeps those versions online.
* **Container archives** (`trackc-bench.tar`, `trackc-cuda-dev.tar`) are inputs to the image
  build; their own rebuild-to-identical was not measured.
* **Runtime additions are by design not reproducible**: libraries a user adds with
  `lazarus-install` come from the live NVIDIA mirror (curated names are version-pinned, other
  package names install the newest version) and live only on that stick's persist partition.
* **Measurements** (boot time, RAM, GPU speed) vary between runs; they are reported as median
  and range of 5-7 runs with raw data in `docs/results/`.
