SECURITY HARDENING

Five concrete measures, checked at every boot

1 · READ-ONLY ROOT

squashfs mounted ro, writes refused. /tmp, /var/tmp, /home: nodev, nosuid, noexec. A self-test checks each one at boot.

2 · UNPRIVILEGED WORKLOAD

User “bench”, rootless Podman, --cap-drop=all, no-new-privileges, --network=none, non-root inside the container, default seccomp.

3 · KERNEL SYSCTLS

kptr_restrict=2, dmesg_restrict, unprivileged BPF off, BPF JIT hardening, Yama ptrace_scope=2, kexec off, SysRq off.

4 · DEFAULT-DENY FIREWALL

nftables input policy drop. Release image: nothing inbound. Dev image: SSH only.

5 · MINIMAL ATTACK SURFACE

No compiler, no package manager metadata; SSH key-only and only in the lab image. The host laptop’s internal disks are forced read-only.

Secure Boot and module signing were left out by decision; dm-verity and AppArmor are next steps.
